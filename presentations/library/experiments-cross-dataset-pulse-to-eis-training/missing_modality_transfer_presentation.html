Predicting Missing Battery Measurements From Partial Test Data

This page explains the full pipeline for batteries that do not all have the same measurements. It learns from complete rows, tests by hiding known measurements, and writes pseudo-labels only with clear uncertainty.

Executive Read

The pipeline is operational: it loaded 917 rows across 5 datasets, found 2 complete datasets with time-series, EIS, and RPT-like labels, and wrote 634 pseudo-label rows.

Current verdict: development_pipeline_operational_with_cross_dataset_support. That wording is intentionally dry. A flashy name would hide the real point: this is a development pipeline for incomplete battery test data, not a validated external claim.

Blunt boundary: pseudo-labels are estimates, not measurements. This completes the development pipeline, not a publication-level external validation claim.

What the pipeline sees

Time-series features, fixed-grid EIS targets, and RPT-like health labels when available.

What it predicts

Missing RPT-like labels from time-series plus EIS, and missing EIS from time-series plus RPT when prediction rows exist.

What works now

Ohmic-proxy EIS beats baseline across five grouped datasets, and dataset-relative RPT beats baseline across the two all-three datasets.

What stays limited

The result is still a development result. A stronger claim needs a future pre-declared all-three battery.

Question

Can we train on batteries with time-series, EIS, and RPT-like labels, then use that learned relationship to fill missing modalities for batteries that only have part of the measurement set?

The honest answer is: yes for the development pipeline. The current supported heads are ohmic-proxy EIS from time-series and dataset-relative SOH from time-series plus EIS.

Plain Language Version

Different battery datasets measure different things. One dataset may have current and voltage traces. Another may have EIS. Another may have health labels. The old name, missing-modality transfer, describes that technically, but it is bad first-glance communication. The practical question is simpler: can we predict a missing battery measurement from the measurements we do have?

The answer is mixed. Some heads are useful inside the current development evidence. Some fail when the held-out dataset is too different. That is why this page separates working development machinery from external validation.

Methodology

Load available matrices

The runner combines cleaned development rows, Molicell rows, and LiFePO4 rows into one modality registry.

Register modality coverage

Each dataset is counted for time-series, EIS, RPT-like labels, and complete all-three rows.

Run masked-modality tests

Known EIS or RPT values are hidden and reconstructed, then compared with a train-mean baseline.

Write pseudo-labels

Missing RPT-like labels are estimated for rows with time-series plus EIS. The output is explicitly marked as pseudo-label data.

This is the right boring discipline: hide known values, predict them, compare against a baseline, and only then use the model to fill missing values. Anything else would be hand-wavy data decoration.

Claim Boundary

Development pipeline. It estimates missing modalities; it does not convert pseudo-labels into measurements.

Do not oversell this. The pipeline is useful because it refuses to blur three different things: real measurements, hidden-measurement tests, and pseudo-labels. If you mix those up, the whole project starts lying to itself.

Conclusion

The pipeline is now a real incomplete-test-data prediction system, not just an EIS predictor. But the current evidence says the generalization claim is not ready.

Supported

  • The runner builds a registry across incomplete batteries.
  • It performs masked-modality tests instead of blindly filling missing data.
  • It writes pseudo-labels with explicit confidence boundaries.
  • DIB and LiFePO4 now both provide complete time-series, EIS, and RPT-like rows.
  • Ohmic-proxy EIS beats baseline across all grouped EIS folds.
  • Dataset-relative RPT heads beat baseline on both all-three grouped folds.
  • The public-site presentation and downloadable artifacts are generated.

Not supported

  • A publication-level cross-battery validation claim.
  • Treating pseudo-labels as measured RPT or EIS.
  • Assuming missing measurements are roughly the same as another battery.
  • Changing the frozen heads after seeing a future held-out validation battery.

Math

The pipeline trains modality heads like this:

f_EIS(time series, RPT) -> EIS spectrum
f_RPT(time series, EIS) -> RPT-like health labels

Each head is judged against a baseline:

relative improvement = (RMSE_baseline - RMSE_model) / RMSE_baseline

A head is not trusted just because it runs. It has to beat the baseline on grouped folds.

def build_frozen_head_development_test(payload: dict[str, Any]) -> dict[str, Any]:
    completed = [
        task
        for task in payload.get("tasks", [])
        if task.get("status") == "completed" and task.get("verdict") == "supports_cross_dataset_transfer_head"
    ]
    preferred_order = [
        "masked_rpt_from_dataset_relative_time_series_plus_eis",
        "masked_rpt_from_dataset_relative_time_series",
        "masked_rpt_from_time_series_plus_eis",
        "masked_eis_from_minimal_time_series_shallow_rf",
        "masked_eis_from_time_series_plus_rpt",
    ]
    selected = None
    for name in preferred_order:
        selected = next((task for task in completed if task.get("task") == name), None)
        if selected:
            break
    if selected is None and completed:
        selected = completed[0]
    all_three = [
        row
        for row in payload.get("registry", {}).get("datasets", [])
        if int(row.get("complete_time_series_eis_rpt_rows", 0)) > 0
    ]
    status = "development_freeze_test_completed" if selected and len(all_three) >= 2 else "blocked"
    return {
        "created_utc": datetime.now(timezone.utc).isoformat(),
        "status": status,
        "selected_head": selected.get("task") if selected else None,
        "selected_model_policy": "Use the already-defined task/model policy from missing_modality_v1_frozen_contract.json.",
        "fold_group": selected.get("fold_group") if selected else None,
        "folds_beating_baseline": selected.get("folds_beating_baseline") if selected else None,
        "fold_count": selected.get("fold_count") if selected else None,
        "worst_relative_improvement_vs_baseline": selected.get("worst_relative_improvement_vs_baseline") if selected else None,
        "all_three_dataset_count": len(all_three),
        "all_three_datasets": [
            {
                "dataset_key": row.get("dataset_key"),
                "complete_time_series_eis_rpt_rows": row.get("complete_time_series_eis_rpt_rows"),
            }
            for row in all_three
        ],
        "claim_boundary": "Development freeze-test only. LiFePO4 RPT labels were mapped during this work, so this is not a clean external validation win.",
    }


def write_frozen_head_development_test_markdown(audit: dict[str, Any], path: Path) -> None:
    lines = [

        f"- Folds beating baseline: `{audit.get('folds_beating_baseline')}` of `{audit.get('fold_count')}`.",

def build_eis_head_blocker_audit(payload: dict[str, Any]) -> dict[str, Any]:
    eis_tasks = [
        task
        for task in payload.get("tasks", [])
        if str(task.get("task", "")).startswith("masked_eis_from")
    ]
    rows = []
    for task in eis_tasks:
        failures = []
        for fold in task.get("fold_error_by_target", []):
            pass
        rows.append(
            {
                "task": task.get("task"),
                "status": task.get("status"),
                "verdict": task.get("verdict", task.get("status")),
                "fold_group": task.get("fold_group"),
                "folds_beating_baseline": task.get("folds_beating_baseline"),
                "fold_count": task.get("fold_count"),
                "worst_relative_improvement_vs_baseline": task.get("worst_relative_improvement_vs_baseline"),
                "mean_relative_improvement_vs_baseline": task.get("mean_relative_improvement_vs_baseline"),
                "failed_fold_count": (
                    int(task.get("fold_count", 0)) - int(task.get("folds_beating_baseline", 0))
                    if task.get("fold_count") is not None and task.get("folds_beating_baseline") is not None
                    else None
                ),
                "failed_target_rmse_by_fold": failures,
            }
        )
    supported = [row for row in rows if row.get("verdict") == "supports_cross_dataset_transfer_head"]
    best = None
    completed = [row for row in rows if row.get("status") == "completed"]
    if completed:
        best = max(
            completed,
            key=lambda row: (
                int(row.get("folds_beating_baseline") or 0),
                float(row.get("worst_relative_improvement_vs_baseline") or -999.0),
            ),
        )
    ready = bool(supported)
    return {
        "created_utc": datetime.now(timezone.utc).isoformat(),
        "status": "eis_head_ready" if ready else "eis_head_not_ready",
        "claim_boundary": "Ohmic-proxy EIS transfer has development support. Pseudo-EIS is still an estimate, not a measurement.",
        "best_current_eis_task": best,
        "eis_tasks": rows,
        "reason": "At least one EIS head beats the baseline on every grouped dataset fold."
        if ready
        else "No current EIS head beats the baseline on every grouped dataset fold.",
        "next_action": "Keep the ohmic-proxy schema frozen for future checks and do not treat pseudo-EIS as measured EIS."
        if ready
        else "Build a better comparable EIS representation or add protocol-compatible all-three data before claiming EIS imputation support.",
    }


def write_eis_head_blocker_markdown(audit: dict[str, Any], path: Path) -> None:
    lines = [
        "# Missing-Modality EIS Head Blocker Audit",
        "",
        f"- Status: `{audit['status']}`.",
        f"- Claim boundary: {audit['claim_boundary']}",
        f"- Reason: {audit['reason']}",
        f"- Next action: {audit['next_action']}",
        "",
        "## EIS Heads",
        "",
    ]
    for row in audit.get("eis_tasks", []):
        lines.append(f"### {row.get('task')}")
        lines.append("")
        lines.append(f"- Verdict: `{row.get('verdict')}`.")
        lines.append(f"- Folds beating baseline: `{row.get('folds_beating_baseline')}` of `{row.get('fold_count')}`.")
        lines.append(f"- Worst relative improvement: `{row.get('worst_relative_improvement_vs_baseline')}`.")
        lines.append("")
    path.write_text("\n".join(lines), encoding="utf-8")

Glossary

TermMeaning
Missing modalityA measurement type that is absent for a battery, such as RPT labels or EIS spectra.
Pseudo-labelA model estimate of a missing measurement. It is not a real measurement.
RPTReference performance test, used here as RPT-like health labels such as SOH or capacity.
EISElectrochemical impedance spectroscopy, represented here on a fixed frequency grid.
Masked-modality testA test where known data is hidden and reconstructed to check whether the imputation head works.
Internal headA model tested only inside the one all-three dataset by held-out cell.
Cross-dataset transferA model tested by holding out a whole dataset, the harder and more honest test.
BaselineThe boring comparison model. If the model cannot beat it, the head is not useful yet.

Limits

  • Keep the ohmic-proxy EIS head and dataset-relative RPT head frozen before any future held-out validation run.
  • Add or identify a cleaner third complete all-three-modality battery before making any general validation claim.
  • Repeat the frozen heads on a future pre-declared all-three battery before making a publication-level claim.
  • Keep pseudo-labels down-weighted or flagged. Do not train future claims as if pseudo-RPT or pseudo-EIS were measurements.

Ruthless version: the development pipeline is complete. The next serious milestone is a clean, pre-declared external validation battery, not more deck polish.
