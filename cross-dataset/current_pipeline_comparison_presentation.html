Two Current Cross-Dataset Pipelines

This page compares two cross-dataset research lanes. Both now have negative external evidence, so neither is generally validated.

Download readiness JSON Download V5 SiCWell result Download final LiFePO4 results

Executive Read

The time-domain-to-EIS pipeline is the stricter validation lane, and it currently says no_support. That is not a disaster. It means the pipeline caught a weak model instead of letting us overclaim.

The missing-measurement V5 pipeline passed internal development, then failed its frozen SiCWell external test. The guard rejected all 892 external rows, so the result is external_validation_failed, no support.

Best one-line meeting answer

Both external paths failed honestly. V5 is a reproducible negative external result, not a general method.

What not to say

Do not say either model is validated. Do not call a V5 estimate a measurement.

What to say instead

The next bottleneck is an untouched, suitable kept-back test and a new frozen version, not post-hoc tuning.

Question

Which cross-dataset pipeline is stronger right now, and which one has the better two-week development outlook?

Pipeline A: Time-domain to EIS

Predict measured EIS spectra from time-domain diagnostic features. This is a hard, direct generalization problem.

Pipeline B: Missing battery measurement prediction

Use time-series, EIS, and RPT/SOH when available, then estimate missing measurements with uncertainty labels.

Recommendation

Lead with the honest negative

The strict time-domain-to-EIS validation lane did not support the learned model. This is a real result, not a failure to hide.

Close V5 honestly

Its SiCWell external test failed. Do not widen the domain guard, remap the data, or call it a near pass.

Do not inflate estimates

Predicted EIS and SOH are pseudo-measurements, not observed values.

Ask for better data, not more tuning

A future version needs a different untouched kept-back test with same-cell EIS, matched pulse resistance, and measured SOH or capacity.

Claim Boundary

Defensible claim: the strict time-domain-to-EIS lane found no support, and V5 missing-measurement development passed internally but found no external support on frozen SiCWell.

Not defensible: claiming either model is generally validated, treating a V5 estimate as measured EIS or SOH, or changing the V5 guard after seeing SiCWell.
