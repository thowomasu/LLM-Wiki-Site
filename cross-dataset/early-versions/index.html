Versions 1 to 3: Early Missing-Measurement Attempts

A plain-language history of the first transfer models, their tests, their failures, and the changes that led to Version 4.

Start here: what the project was trying to do

A battery pulse is a short burst of current. It is cheap and fast to record. EIS is a slower laboratory measurement that shows how the battery responds across many frequencies. The project asked whether the cheap pulse could help reconstruct a missing EIS measurement and then estimate battery health.

Versions 1 to 3 were the first attempts. They matter because they exposed the core problem: a model can look good on familiar data and still fail when the battery type or test procedure changes.

ModelA fixed calculation learned from development data.
BaselineA simple fallback prediction. The model is useful only if it beats this.
Internal testA whole cell is held back, but it still comes from the same dataset family used for development.
External testA different dataset is tested only after the method and pass rules are locked.
Bottom line:

Versions 1 to 3 produced useful lessons, not outside proof. Version 1 missed its outside-data rule. Version 2 was not complete enough to lock for a new outside test. Version 3 missed the rule requiring all three outputs to pass.

No external support

Version 1: the first broad transfer model

What it did

Version 1 converted pulse voltage and current into resistance-like features. An Extra Trees model used those features to predict the real and imaginary parts of EIS from 0.1 to 40 Hz.

1. Read pulseSummarize voltage change, current, duration, and throughput.
2. Build proxiesDivide voltage changes by current-like quantities to form resistance-style inputs.
3. Predict EISEstimate the spectrum on the shared frequency grid.
4. CompareTest the fixed model against a simple EIS baseline on CMU Samsung data.

What happened

External rows179
Model EIS typical prediction error0.0209 ohm
Baseline EIS typical prediction error0.0131 ohm
Relative result-59.8%

The negative percentage means the model was worse, not better. Its error was about 59.8% higher than the baseline. The health model could not be scored because the CMU spectrum did not include the frozen 0.05 Hz input. The full predicted-EIS-to-health chain was also outside the Version 1 contract.

Why it failed:

The resistance-style pulse features did not transfer reliably to the different CMU measurement domain. The correct response was to lock the failure and redesign the development process.

Development only

Version 2: separate the problem and add calibration

What changed

Version 2 stopped treating EIS as one large output. It trained separate models for real EIS and imaginary EIS, compared smaller feature sets, and later used a fresh same-cell EIS reference plus pulse-resistance change. It also added an SOH model.

In simple terms, Version 2 asked a narrower question: if we know how this exact cell looked when fresh, can a later pulse help predict how its spectrum and health changed?

What worked internally

The calibrated Leonardi test used seven development cells and held back Cell 08 inside the same dataset. On that internal cell, all three heads beat their baselines:

Real EIS improvement83.3%
Imaginary EIS improvement75.2%
SOH improvement76.5%

Why this still was not external support

The earlier general comparison used 917 development rows. The real-EIS model was stable enough to lock, but the imaginary-EIS model did not pass every repeated held-cell check. Because both were required, the complete Version 2 method was not ready to lock for a new outside test. The separate calibrated Leonardi result still came from the same dataset family.

Cassino could not provide the frozen longitudinal inputs or SOH target. Scoring it would have required changing the rules after inspecting the dataset, so its verdict was blocked_inconclusive.

Lesson:

Same-cell calibration helped, but it also narrowed the required data contract. A dataset with EIS alone was no longer enough to test the complete method.

External validation failed

Version 3: make the inputs more portable

What changed

Version 3 removed cycle number and open-circuit voltage from the model because those values are defined differently across laboratories. It kept the calibrated fresh-EIS reference, pulse-resistance change, and Extra Trees models.

Why it looked promising

Eight leave-one-cell-out Leonardi folds passed for real EIS, imaginary EIS, and SOH. The worst-cell improvements were 83.9% for real EIS, 75.7% for imaginary EIS, and 81.1% for SOH.

The Bayreuth outside-data test

The model and pass rules were locked first. The final Bayreuth answers had not been used to choose or change them. The locked model was then scored once on 14 Bayreuth cells and 28 rows. Every output model had to improve on its simple comparison by at least 5%.

Real EIS improvement0.34%
Imaginary EIS improvement0.45%
SOH improvement74.7%

SOH passed, but both EIS heads missed the 5% gate by a wide margin. Because all three heads were required, the final verdict was external_validation_failed with no support.

Why it failed:

The portable inputs helped inside Leonardi but did not produce a meaningful EIS advantage on Bayreuth. Strong repeated checks within Leonardi could not override the outside-data result. Here, “failed” means the result missed a rule fixed in advance, not that the software crashed.
