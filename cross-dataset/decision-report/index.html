Cross-Dataset Decision Report

A physics-first explanation of what worked, what failed, and what should happen next.

Skim firstThe universal model is not supported. Parts of EIS can be estimated, but the EIS-to-health relation does not transfer reliably. The next useful study must use a physically matched domain.

Cross-Dataset Pipeline: Clear Findings and Next Decision

Read this first

The present universal analysis chain should not be improved by adding a more complicated model.

The main problem is that the datasets describe different physical and experimental domains.

The analysis chain can often estimate parts of an impedance spectrum.

It cannot convert those estimates into a reliable State of Health result across all datasets.

Small amounts of calibration data did not solve this problem.

The present safety check also failed.

It accepted every sample, including many samples with poor predictions.

The best next step is a narrow-domain feasibility study.

This study should first identify datasets with genuinely comparable cells and measurement protocols.

The study should then test whether predicted EIS adds useful information beyond pulse data alone.

If no useful common domain exists, the universal prediction project should end.

---

The scientific question

The proposed chain is:

pulse response → estimated EIS → estimated State of Health

The idea is useful only if each arrow adds reliable information.

The complete chain must also work on a dataset that was not used to construct it.

Good results on another cell from the same experiment are not enough.

Cells from one experiment usually share chemistry, equipment, temperature, test procedure, and data processing.

A model can therefore work inside one experiment and still fail on a different experiment.

That is what the present evidence shows.

What worked

Parts of the EIS spectrum could often be estimated

The real part of impedance was the strongest result.

One normalized description of the measurements beat its simple reference in all four dataset tests for the real part of impedance.

This result does not validate the complete analysis chain.

It shows that pulse information can contain a transferable relation to one part of the impedance response.

The imaginary part was less stable.

Most dataset tests improved, but at least one dataset became substantially worse.

This instability matters because the imaginary part carries information about time-dependent electrochemical processes.

Some individual datasets gave strong cell-to-cell results

The Leonardi dataset gave consistently strong results when one cell was held out.

SiCWell also gave good median results for many cells.

These results show that a narrow model may be possible inside a controlled experimental domain.

They do not show that one model transfers between unrelated datasets.

---

What failed

EIS did not provide a stable cross-dataset State of Health estimate

Measured EIS did not beat its simple State of Health reference consistently.

The result passed on only one of four held-out datasets with the stronger nonlinear model.

The median result was worse than the reference.

This is important.

If measured EIS does not transfer reliably to State of Health, estimated EIS cannot repair that weakness.

The complete chain failed

The estimated-EIS-to-State-of-Health chain passed on only one of four held-out datasets in the reference study.

Its median performance was worse than the simple reference.

The error therefore enters at more than one point.

The pulse-to-EIS step is imperfect.

The EIS-to-State-of-Health relation also changes between datasets.

Combining both steps compounds the mismatch.

Alternative EIS descriptions did not rescue the result

The study tested several ways to describe the spectra.

These included dimensionless changes, reduced frequency sets, scale-and-shape separation, and a small hybrid description of the measurements.

No description of the measurements passed every required dataset-level test.

The failure was therefore not caused by one obviously poor choice of EIS coordinates.

One-cell and two-cell calibration did not solve the transfer problem

The study allowed a small number of cells from the target dataset for calibration.

No tested calibration method passed all required tests.

Some individual quantities improved.

The complete chain did not become reliable across several datasets.

This means that a small correction of scale or offset is not enough.

The safety check was unsafe

The safety check was intended to refuse predictions outside the known domain.

Instead, it accepted all 1,383 rows.

Among the accepted rows, 1,062 were unsafe for at least one part of the chain:

Physical interpretation

The datasets are not interchangeable

Impedance depends on more than ageing.

It also depends on chemistry, cell construction, temperature, SOC, rest history, excitation amplitude, frequency range, and measurement equipment.

Pulse resistance depends on pulse duration, direction, current amplitude, SOC, temperature, and the chosen voltage interval.

State of Health also depends on how reference capacity is defined and measured.

Normalizing the numbers cannot guarantee that these physical meanings become equal.

Similar numerical features can represent different processes

A resistance increase can arise from several mechanisms.

Examples include contact resistance, charge-transfer changes, transport limitations, and temperature differences.

Two datasets can therefore show a similar resistance change for different physical reasons.

This weakens a universal pulse-to-EIS relation.

State of Health is the weaker link

The results suggest that estimating parts of EIS is easier than mapping EIS to a common State of Health value.

This is physically plausible.

EIS describes the cell response at a particular condition.

State of Health compresses degradation into one label.

Different datasets may define and measure that label differently.

The same impedance change can therefore correspond to different reported State of Health values.

---

What should be improved now

Priority 1: Define a common physical domain

Create one comparison table for every dataset.

The table must include:

  • Cell chemistry and format.
  • Nominal capacity.
  • Ageing procedure.
  • Temperature during pulse, EIS, and capacity measurements.
  • SOC during pulse and EIS measurements.
  • Rest time before each measurement.
  • Pulse direction, amplitude, and duration.
  • Definition of pulse resistance.
  • EIS frequency range and excitation amplitude.
  • State of Health definition.
  • Number of cells and repeated check-ups.

Every field should be marked as matched, different, or unknown.

Unknown information must not be treated as matched information.

Only a physically defensible subset should continue to modelling.

Priority 2: Test the value of each measurement

The next comparison should contain four separate questions:

QuestionPurpose
Can pulse data estimate State of Health directly?Establish the simplest useful method
Can measured EIS estimate State of Health?Test whether EIS adds health information
Can pulse data estimate EIS?Test the missing-measurement idea
Does estimated EIS improve State of Health prediction?Test whether the complete chain is justified

The estimated EIS stage should be removed if direct pulse-to-State-of-Health prediction performs equally well.

The complete chain should stop if measured EIS does not beat pulse data alone.

Priority 3: Judge datasets and cells separately

The main result should be the performance for each held-out dataset.

The report should also show the median cell and the worst cell.

The total number of measurement rows should not determine the conclusion.

This prevents a large dataset from hiding failure on smaller datasets.

Priority 4: Replace the current safety check

The first safety check should be based on experimental metadata.

It should refuse a prediction when chemistry, temperature, SOC, or measurement procedure is outside the declared domain.

A numerical similarity score may be added later.

A numerical score should not replace missing physical metadata.

The output should use four clear states:

  • Prediction allowed
  • Target calibration required
  • Prediction refused
  • Insufficient information

Priority 5: Add automatic scientific checks

The analysis should stop automatically when:

  • The same cell appears in development and evaluation data.
  • Calibration cells also appear as evaluation cells.
  • Units or impedance sign conventions disagree.
  • The requested frequency lies outside the measured frequency range.
  • SOC or temperature lies outside the declared range.
  • A required measurement condition is missing.
  • A result contains only pooled row statistics.
  • A frozen external test setting has changed.

These checks protect the scientific claim.

They are more valuable than adding another complex prediction method.

---

Recommended next study

Study title

Feasibility of a protocol-matched pulse-to-EIS-to-health model

Step 1: Build the compatibility table

Use the four existing development datasets.

Do not train a new model during this step.

Step 2: Select a domain for physical reasons

A valid domain should match chemistry, temperature, SOC, pulse definition, EIS conditions, and State of Health definition.

Do not select a domain because it gives the best numerical result.

Step 3: Check whether enough independent cells remain

Use at least eight development cells.

Keep at least three cells completely untouched for final evaluation.

If this is impossible, stop the modelling study.

Step 4: Compare the four measurement questions

Start with direct pulse-to-State-of-Health prediction.

Then test measured EIS.

Test estimated EIS only after those two results are understood.

Test the complete chain last.

Step 5: Apply a hard stopping rule

Stop if the complete chain does not beat the best simple alternative.

Stop if the worst-cell result is physically unacceptable.

Stop if the supported domain becomes so narrow that it describes only one test campaign.

---

Decision

Do not search for another universal model.

Do not search for a new external kept-back test for the present model.

No present candidate passed the development requirements.

Proceed with the compatibility table and the four-part measurement-value comparison.

Continue modelling only if a useful and physically coherent domain remains.

Otherwise, close the analysis chain as a well-supported negative result.

---

Limits of this report

This report uses existing frozen results.

No model was retrained.

No threshold was changed.

No new dataset was scored.

The report does not prove that every chemistry-specific or protocol-specific model will fail.

It shows that the tested universal model is not supported.
