CALB L148N58A Pulse-To-EIS Pipeline Viability

This page uses the same structure as the cross-dataset presentation: question, method, results, conclusion, inputs, math, graphs, code, outputs, glossary, and limits. The truth is mixed: the internal pulse bridge is strong, the drive-cycle extension is weak, and external validation is still blocked.

Executive Read

The CALB pipeline has a real internal result: frozen pulse-to-EIS rule produces 246 quality-pass rows out of 246 for same-dataset HPPC pulse-to-EIS bridging.

Blunt boundary: this is not external validation. external-validation limit of the evidence says repeat test on outside data is blocked, leakage and claim audit labels the claim as internal_engineering_result_not_clean_holdout_or_external_validation, and SOC-stratified drive-cycle audit says the drive-cycle result is SOC-misaligned with the ECM baseline still stronger.

What works

The internal HPPC-to-EIS bridge passes quality gates across 10 C, 25 C, and 40 C.

What got weaker

The drive-cycle transfer looked better than a baseline-only comparator in drive-cycle transfer test, then lost to a stronger ECM baseline in drive-cycle ECM baseline check.

What blocks the bigger claim

No defensible external dataset has run the frozen frozen pulse-to-EIS rule unchanged and beaten the required baseline.

What to say if challenged

Do not claim broad validation. Say the internal bridge is viable, drive-cycle support is limited, and external validation is blocked.

Question

Can CALB HPPC pulse windows reconstruct or approximate same-cell EIS behavior well enough to justify a pulse-to-EIS pipeline?

The honest answer is yes for internal CALB pulse-bridge evidence. It is not yes for external validation, and it is not yes for unrestricted drive-cycle claims.

Methodology

The pipeline uses paired CALB HPPC and EIS records from the same study. It builds candidate pulse windows, fits time-domain DRT-style behavior, compares against measured EIS-derived targets, then audits the result through later sections.

Load CALB archive-derived outputs

Use parsed local files from the CALB package, not a loose manual spreadsheet.

Build HPPC pulse candidates

Identify pulse/rest windows around HPPC events and track temperature, cell, protocol, and EIS record.

Fit internal pulse bridge

Apply the final adaptive multitemperature rule over HPPC protocols at 10 C, 25 C, and 40 C.

Audit drive-cycle transfer

Test whether HPPC-derived dynamics help on held-out drive-cycle voltage, then compare against stronger ECM baselines.

Check claim boundaries

Run regression, SOC alignment, uncertainty, leakage, ablation, and external-readiness audits before saying what is supported.

The input package is the CALB L148N58A local output folder. The important boundary is that this is one source study. Same-study internal success is not the same thing as external validation.

Feature-To-Target Math And Scoring Logic

This presentation is not pretending the CALB pipeline and the cross-dataset supervised model are identical. The page structure matches. The math is the CALB bridge math.

pulse window: x(t) = [I(t), V(t), T, SOC context, rest/pulse timing]
internal target: y = measured EIS-derived behavior for the same cell, temperature, and diagnostic context
quality gate: pass if pulse/EIS alignment, correlation, OCV delta, and time-fit error stay inside the declared rule
drive-cycle test: compare fixed HPPC-derived dynamics against baseline and ECM variants on held-out dynamic voltage
Weak spot:

The drive-cycle extension is where the story breaks. drive-cycle ECM baseline check found median DRT kept-back test RMSE of 150.9172 mV versus 134.8626 mV for the best ECM baseline.

def write_json(path: Path, data: object) -> None:
    path.parent.mkdir(parents=True, exist_ok=True)
    path.write_text(json.dumps(data, indent=2, allow_nan=False), encoding="utf-8")

Glossary

Short definitions for the terms used in the deck.

TermPlain meaning
CALBCell manufacturer and dataset shorthand for L148N58A prismatic cells.
EISElectrochemical Impedance Spectroscopy, the measured impedance target.
HPPCHybrid Pulse Power Characterization, the pulse protocol used for the internal bridge.
DRTDistribution of Relaxation Times, the relaxation representation used in the analysis.
ECMEquivalent Circuit Model, the stronger drive-cycle baseline in drive-cycle ECM baseline check.
SOCState of Charge. The drive-cycle SOC mismatch is one of the main weak spots.
Frozen ruleA rule that should not be retuned after seeing external data.
External validationNot achieved here. external-validation limit of the evidence still blocks it.

What This Proves, And What It Does Not

Supported

  • CALB internal HPPC pulse-to-EIS bridge readiness.
  • Regression-checked frozen pulse-to-EIS rule output with 246 quality-pass rows.
  • Clear evidence that drive-cycle transfer needs stricter wording.
  • Public packaging with data, plots, summaries, code snippets, and claim boundaries.

Not supported

  • No external validation claim.
  • No claim that drive-cycle DRT beats the best ECM baseline.
  • No retuning of the frozen CALB frozen pulse-to-EIS rule to rescue failed external checks.
  • No claim that one CALB source study proves broad cross-dataset generalization.

Conclusion

The CALB presentation now matches the cross-dataset page structure and reader experience. The technical story is intentionally harsher: internal CALB pulse-to-EIS evidence is viable, drive-cycle evidence is limited, and external validation remains blocked.
